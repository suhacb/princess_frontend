# Handoff: Princess Design System → Angular Frontend

## Overview
This package documents the **Princess Design System** — the complete visual language and component library for the **Princess** PRINCE2 project-management application (Sinecon). It covers design tokens (color, type, spacing, elevation), 18 UI components, and the assembled app shell (sidebar, top bar, four screens).

The target implementation is the existing **`princess_frontend` Angular app** (Angular 22, standalone components + signals, Angular Material 3 on the azure-blue theme, component-scoped SCSS). This document gives a developer using Claude Code everything needed to build/verify these components in that codebase.

## About the Design Files
The files in `reference_files/` are **design references authored in HTML/React (JSX)** — prototypes that demonstrate the intended look, states, and behavior. **They are not production code to copy.** The task is to **recreate them in the `princess_frontend` Angular environment** using its established patterns: Angular Material 3 components, the app's `_theme-vars.scss` token map, signals for state, and component-scoped SCSS — per the rules in `princess_frontend/CLAUDE.md`.

Where a component maps to an Angular Material primitive (button, checkbox, select, dialog, etc.), **wrap/theme the Material component** rather than building from scratch. Where there is no Material equivalent (AI suggestion card, lifecycle stepper, risk score badge), build a standalone standalone component using the documented values.

### Open the reference
`reference_files/` is a runnable visual mirror. Open `reference_files/ui_kits/princess/index.html` — a **single self-contained file** (React, the compiled component bundle, all four screens, and the app shell are inlined) — to explore the full interactive app offline. Open the per-section showcase cards (`reference_files/components/**/**.card.html`) to inspect each component live (these load the compiled `_ds_bundle.js`). Every component's exact values are tabulated in this README; the token CSS source is in `reference_files/tokens/`.

## Fidelity
**High-fidelity (hi-fi).** All colors, typography, spacing, radii, shadows, sizes, and interaction states are final and exact. Recreate pixel-for-pixel using the codebase's Material 3 theme and SCSS. Every value a developer needs is tabulated below; the source CSS lives in `reference_files/tokens/`.

## Components

18 components. **Map** = recommended Angular Material 3 target. Each is documented below with exact values; see it rendered live in `reference_files/components/<group>/<group>.card.html`.

### Buttons

**Button** — `mat-button` family (`mat-flat-button` filled, `mat-button` tonal/text, `mat-stroked-button` outlined).
- Shape: pill, `border-radius: 20px`. Font: Instrument Sans 500, letter-spacing `.01em`. Gap 8px between icon/label. Icons: Material Icons, 18px.
- Sizes: `sm` 32px tall / `0 14px` / .8125rem · `md` 40px / `0 22px` / .875rem · `lg` 48px / `0 28px` / .9375rem. Text variant uses 14px side padding.
- Variants & states:
  - **filled**: bg `--mat-sys-primary`, text `--mat-sys-on-primary`. Hover → `color-mix(primary 90%, #000)` + elevation-1. Active → `color-mix(primary 82%, #000)`.
  - **tonal**: bg `--mat-sys-secondary-container`, text `--mat-sys-on-secondary-container`. Hover → mix 88% #000.
  - **outlined**: transparent, text `--mat-sys-primary`, border `--mat-sys-outline-variant`. Hover → bg `primary 8%` tint, border → primary.
  - **text**: transparent, text primary. Hover → `primary 8%` tint.
  - **danger**: bg `--mat-sys-error`, text on-error. Hover → mix 90% #000 + elevation-1.
  - **disabled**: opacity .38, no shadow, `not-allowed`.
  - **focus-visible**: focus ring token.

**IconButton** — `mat-icon-button`.
- Round, transparent, color `--mat-sys-on-surface-variant`. Sizes: `sm` 32px (icon 18px) · `md` 40px (icon 22px).
- Hover → bg `on-surface 8%`, color on-surface. Active → bg `on-surface 14%`. `active` prop → color primary. Disabled opacity .38.
- Optional **badge**: top-right, min 16px tall, `padding 0 4px`, radius 8px, bg `--mat-sys-error`, white Instrument Sans 600 10px.

## Interactions & Behavior
- **Buttons / chips / icon buttons / tabs / inputs / selects**: hover, active, focus-visible, disabled states as tabulated. All transitions `200ms cubic-bezier(0.4,0,0.2,1)` (checkbox check 120ms).
- **Select**: click toggles a tonal menu (elevation-2); closes on outside `mousedown`; selected option flagged with `check`.
- **Input**: label floats on focus, non-empty value, or when a placeholder is set; error message replaces hint and recolors border + label.
- **Tabs / Checkbox / Switch / Select**: support controlled and uncontrolled use (Angular: model via signals / `[(ngModel)]` / reactive forms).
- **AI accept/dismiss**: accept applies the proposed change; dismiss removes the card (simulated in the prototype).
- **Skeleton**: infinite shimmer, disabled under reduced-motion.
- In Angular, drive all view/UX state transitions with **signals** (`signal`, `computed`, `effect`) per `CLAUDE.md` — no NgRx.

## State Management (Angular guidance)
- Use plain `@Injectable` services with signals for shared state (mirror `AuthStore`). Local component state via `signal()`/`computed()`.
- Table screens: signals for query, filters, sort key, and a `computed()` derived/filtered list.
- Forms: Angular reactive forms or signal-backed models; validation drives the Input `error` state.

## Styling rules (from `princess_frontend/CLAUDE.md`)
- **Never** use generic Material colors — reference the design-system tokens / `_theme-vars.scss` (`--princess-*`, `--mat-sys-*`, the brand/status/score additions documented here).
- Component-scoped SCSS only; avoid global styles.
- **Never** use global `::ng-deep`. To style a Material overlay (`mat-dialog`, `mat-menu`, `mat-select` panel), use the component's `panelClass` and style it in `src/styles/overlays.scss`.
- Verify each component visually (Playwright) for clipping / overlay alignment before marking complete.

## Iconography
Material Icons (filled) is the primary icon font; Material Symbols Outlined is also loaded. Icon ligatures are referenced by name throughout (e.g. `add`, `search`, `notifications_none`, `more_vert`, `auto_awesome`, `expand_more`, `check`, `close`, `folder_open`, `inbox`).
